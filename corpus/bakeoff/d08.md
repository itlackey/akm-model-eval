## Five headline findings (data-grounded)

### 1. 🔴 Distill is silent dead code — has not produced a proposal in 25 consecutive runs

**Evidence:** 108 distill attempts in the post-fix window (2030-05-19T17:00Z → 2030-05-20T18:07Z), **100% outcome=skipped, 0 proposals queued.** Root cause: `config.llm.features.feedback_distillation` is `null` (default `false`); `tryLlmFeature` returns null without calling the LLM. The "feedback distillation is disabled or the LLM call failed; no proposal created" message conflates config-gate-off with LLM failure — operator cannot tell which.

**Cost:** 1,610 phantom `distill_invoked` events lifetime, planner cycles wasted scoring 7-10 refs per run that immediately become skipped, misleading metrics.

### 2. 🔴 `Asset no longer exists on disk` is the biggest reject category — 604 of 1407 rejects (43%)

**Evidence:** `akm proposals --status rejected | jq '[.proposals[]|.review.reason]|group_by(.)|map({reason:.[0],count:length})'`. Improve is generating proposals against assets that no longer exist on the filesystem. Root cause: planner reads candidate refs from index/state.db, not from filesystem-of-truth.

**Cost:** Single largest reject class. None of yesterday's pipeline fixes addressed this — they hardened the LLM-output validators while this defect is upstream in candidate selection.

### 3. 🟡 The "409 broken proposals avoided per run" framing I've been using is wrong

**Recalibration:** The 409 `distill-skipped` actions per run are mostly **`reflect cooldown (pre-filtered)` (402) + `derived-memory-reflect-skipped` (7)** — completely unrelated to yesterday's recursive-lesson guard. The actual recursive-lesson guard fires ~2 per run (16 hits across 30 runs).

The cooldown pre-filter IS valuable (10,087 lifetime skips per `akm health`) — but it predates the pipeline-fix wave. Attributing it to the new validators overstated their measured value.

## Process / operational issues to address

- **`outcome: "skipped"` semantics are too loose.** Today it conflates: (a) candidate filtered out, (b) feature gate off, (c) LLM call returned null, (d) LLM call errored, (e) validator rejected output. Each is a different action item; the user can't tell which.
- **`warnings: string[]` (49 push sites in consolidate alone) is unconsumed free-form text.** No structured aggregation. Should be `rejections: Record<reason, count>`.
- **Smart-skip patterns mask LLM bugs.** When the LLM has been failing for 17 consecutive runs, the gate silences it. Distinguishing real failures from intentional skips is more important than the user-facing "graceful no-op."
- **`init --dir` write-guard not yet shipped** despite the operational lesson from `akm-init-persists-stashdir-warning`. The wave-implementation memo flagged it; code-level guardrail remains a 1-hour follow-up.

## v0.8.1 updates (applied 2030-06-05)

- **`session-log-failures` advisory is now INFORMATIONAL ONLY** — never triggers a warn in v0.8.1. Any prior documentation or logic treating it as a real alert is incorrect.
