## Command Overview

`akm proposal drain` is a new CLI verb introduced to deterministically process the standing pending backlog of proposals that were not auto-accepted during an `akm improve` run. It operates on the stash directory and applies user-configurable policies to promote, reject, or defer proposals based on generator identity, diff size, and age.

## Usage

```bash
akm proposal drain \
  --policy <preset|path> \
  --dry-run \
  --yes \
  --max-accepts <N> \
  --max-diff-lines <N> \
  --older-than <days> \
  [--judgment] \
  [--profile <improve-profile>]
```

### Flags

- `--policy`: Policy preset (e.g., `personal-stash`) or path to a custom policy file. Determines which proposals are eligible for promotion.
- `--dry-run`: Lists what would be accepted/rejected/deferred without making changes.
- `--yes`: Required in non-interactive mode for any promotion (matches existing bulk-accept behavior).
- `--max-accepts`: Hard ceiling on how many proposals to promote per run.
- `--max-diff-lines`: Defers proposals exceeding this diff size threshold.
- `--older-than`: Only considers proposals older than N days.
- `--judgment`: Enables the optional judgment tier (llm/agent/sdk) for mid-band/duplicate detection and contradiction escalation. No-op if no runner is configured.
- `--profile`: Read triage block from this improve profile; merges with policy fields.

## Behavior

1. **Scans pending backlog**: Fetches all proposals with `status: "pending"` from the stash directory.
2. **Applies policy**: Filters by generator/source and applies rules (e.g., reject empty diffs, defer large changes).
3. **Respects cooldowns**: Avoids re-queueing recently auto-accepted or rejected items to prevent thrashing.
4. **Promotes or rejects**: Calls `akmProposalAccept` or `akmProposalReject` from `src/commands/proposal.ts` to update proposal state and emit events (`promoted`, `rejected`).
5. **Judgment tier (optional)**: For deferred items, optionally invokes an LLM/agent runner to make a final decision.

## Reused Components

- `listProposals(stashDir, { status: "pending" })` from `src/core/proposals.ts`.
- `akmProposalAccept` / `akmProposalReject` wrappers from `src/commands/proposal.ts` (preferred over direct `promoteProposal` calls to ensure events are emitted).
- `resolveImproveProcessRunnerFromProfile` for the judgment tier (llm default, agent/sdk fallback).
- `confirmDestructive` from `src/cli/confirm.ts` for bulk confirmation.

## Integration with Improve

Triage can run as a pre-pass to `akm improve` when configured in the profile (`processes.triage.enabled: true`). This ensures the backlog is cleared before reflect/distill/consolidate runs, avoiding duplicate proposals and wasted LLM tokens. The dry-run path skips the lock and triage entirely.

## Data Safety

Promotion commits to git; a per-proposal `akm proposal revert` exists (restores backup captured at promotion time), but there is **no batch revert**. Wrong bulk drains must be undone one ID at a time. Hard data-safety guardrails are enforced via `--max-accepts`, `--dry-run`, and `--yes`.

## Configuration Schema

Triage config lives in `ImproveProcessConfigSchema` (`src/core/config-schema.ts`) with fields:

- `applyMode`: `"queue"` (default) or `"promote"`.
- `policy`: String policy name or path.
- `maxAcceptsPerRun`: Integer ceiling.
- `maxDiffLines`: Integer diff-size threshold.
- `rejectEmpty`: Boolean to reject empty diffs.
- `judgment`: Optional `{ mode, profile, timeoutMs }` for the judgment tier.

## CLI Command Definition

Defined in `src/cli.ts` as `proposalDrainCommand` under `proposalCommand.subCommands`. The command resolves policy from flags or profile, confirms destructive actions via `confirmDestructive`, and executes the drain logic via `drainProposals(opts)`.
