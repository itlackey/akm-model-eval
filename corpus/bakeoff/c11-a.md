When implementing the Gateway reverse proxy for native AgentRuntime calls (`/oc/*`), the `forwardSessionCreate` function constructs session titles using the format `${principal.channel}:${target.sessionKey}` (colon-separated). This aligns with the design contract (§3.4).

However, existing buffered paths (e.g., `/channel/inbound`) use a slash-delimited format (`${channel}/${sessionKey}`). Because these formats differ, a session created via the proxy and one created via the buffered path for the same logical channel+key will have different titles.

**Impact:** Reattachment logic that relies on matching by title alone cannot unify sessions across these two namespaces. They are effectively separate session stores.

**Recommendation:** Treat proxy-created sessions and buffered-path sessions as distinct namespaces. Do not attempt to merge them based on title similarity; instead, rely on the ownership map (for proxy) or title cache (for buffered) for authorization within their respective scopes.
