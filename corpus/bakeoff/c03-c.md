# Consolidation LLM Profile Resolution

The `akmConsolidate` command now implements a specialized LLM resolution pattern, mirroring that used by other passes like `extract` and `reflect`. This allows users to pin a dedicated model (e.g., a smaller, faster model like Ministral-3b) specifically for the memory consolidation task, rather than relying solely on the global default LLM configuration (`defaults.llm`).

## Resolution Priority

The system resolves the required `LlmConnectionConfig` using the following priority:

1. **Process Override:** Check `config.profiles?.improve?.default?.processes?.consolidate`. If a profile is defined here, it is used via `resolveImproveProcessRunnerFromProfile`.
2. **Global Default:** Fall back to `getDefaultLlmConfig(config)` if no process-specific override exists.

## Technical Context

This change addresses a critical regression where the consolidation pass previously ignored any dedicated profile set for it, silently defaulting to the global LLM configuration. This often led to silent token budget mismatches or runtime errors when users intended to use a lighter model for this specific task.
