# AKM Test Command Patterns

This document defines the exact `bun run` commands for unit tests, integration tests, and the full check gate.

## Purpose

To provide a single source of truth for running test suites in the AKM project, ensuring consistent execution environments and preventing cross-contamination between unit and integration tests.

## When to use

- **Unit Tests:** Use `bun run test:unit` for fast, isolated testing of business logic.
- **Integration Tests:** Use `bun run test:integration` for testing I/O, database connections, and external services.
- **Full Gate:** Use `bun run check` before pushing code to verify linting, type safety, and all tests pass.

## Commands Reference

| Command | Description |
| :--- | :--- |
| `bun run test:unit` | Runs the unit test suite (`tests/unit`). Excludes integration tests. |
| `bun run test:integration` | Runs the integration test suite (`tests/integration`, `tests/commands`, `tests/workflows`). |
| `bun run check` | The pre-push gate: runs linting, TypeScript checks (`--noEmit`), and both unit and integration tests. |

## Critical Constraints

**Never run bare `bun test ./tests` over the whole tree in ONE parallel pool.**

Unit and integration tests share process-level environment variables (e.g., `AKM_STASH_DIR`) and singletons (config/output-mode). Running them together under `--parallel` causes:
1.  **Environment Pollution:** Tests fail with errors like `cli-errors 'search without stash dir'`.
2.  **Singleton Leaks:** The in-process harness singleton-leak test fails due to state contamination.

**CI Strategy:** CI deliberately splits these into separate passes (`test:unit` and `test:integration`) to avoid these issues.

## Configuration

The `bunfig.toml` configuration file preloads `tests/_preload.ts` for all runs. This script:
- Sandboxes `HOME`, `XDG`, and `AKM` environment variables.
- Sets the current working directory (`cwd`).
- Manages `fetch` behavior.
- Sets a global timeout of 30,000ms.
