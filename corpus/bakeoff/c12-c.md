# Print MD Independent Rendering

This document explains the architectural behavior of the `document-renderer` preview server regarding markdown file processing, specifically focusing on the implications of independent rendering and state management.

## Core Behavior

The preview server renders markdown files independently. The implementation in `index.ts` iterates over manifest files and appends rendered content using:

```typescript
bodyContent += md.render(content) + chr10
```

Because each file is processed separately, the `markdown-it` parser state (including flags like `chapterOpen` or `pageOpen`) resets at the end of each file. However, the rendered HTML divs persist in the concatenated output string.

## The EOF Scope Leak

Any layout marker scope that is not explicitly closed at a file's End-Of-File (EOF) becomes a "silent ancestor" div that wraps every subsequent file's content in the final output.

This creates three critical issues:

1. **Plugin Responsibility**: Any plugin that opens wrapper divs MUST ensure they are closed at EOF. Failure to do so causes state leakage across files.
2. **CSS Scope Collision**: CSS rules scoped to `.page.X` or `.chapter.X` can inadvertently match content from completely unrelated files if those wrappers leaked. This breaks visual isolation.
3. **Paged.js Inheritance**: When Paged.js clones content into output pages, it inherits the leaked nesting structure, leading to broken pagination or layout artifacts.

## Actionable Guidance

Always verify EOF cleanup in `markdown-it` plugins that emit wrapper tokens. If a plugin opens a container, it must close it before the file processing completes.
