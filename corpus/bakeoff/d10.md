## Architecture

The AKM harness-redesign report identified that the original test suite ran each file in its own process. The new design consolidates all tests into a single process to improve speed and simplify setup, but this introduces cross-file contamination risks via shared `process.env`.

## Isolation mechanism

The sandbox helpers (`sandboxXdgCacheHome`, `sandboxXdgConfigHome`, `sandboxXdgDataHome`, `sandboxXdgStateHome`, `sandboxStashDir`) create unique temporary directories for each test file and assign them to environment variables. However, because the suite is shared-process, these assignments can be overwritten by other files' setup/teardown code.

## Best practices

- Always use sandbox helpers for any env var that points to a per-test or per-file directory.
- Re-assert env vars in `beforeEach` if your fixture is built once in `beforeAll` and tests are read-only.
- Clean up in `afterEach` to prevent state leakage between tests.

## Evidence

The migration of four test files to use sandbox helpers and explicit re-assertion resulted in zero failures across 3848 total unit tests, confirming that the shared-process model works when isolation is properly implemented.
