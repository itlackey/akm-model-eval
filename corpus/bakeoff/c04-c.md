The `memoryInference` process in `akm improve` (and `akm-improve-quick`) is designed to be idempotent. It relies on a generic LLM-result cache (`withLlmCache` in `src/indexer/llm-cache.ts`) that wraps every inference call.

**Mechanism:**
1.  The pass collects parent memories that lack the frontmatter key `inferenceProcessed: true` (or are not yet derived).
2.  For each pending parent, it computes a body hash and checks the LLM cache.
3.  If the cache contains a valid result for that hash, the inference is skipped entirely (`onCacheHit` fires, but no new memory file is written).
4.  Only when the body changes (new session content) does the LLM run, write a derived child, and mark the parent as processed.

**Observed Behavior:**
-   The `improve_completed` events show `memoryEligible` counts (e.g., ~2006) but very low `memoryInferenceWrites` (0–2) per run.
-   This is not a failure; it indicates the system correctly identifies that most parents are already processed or unchanged.
-   Runs taking ~33ms with 0 writes confirm cache hits are dominating the workload, preventing unnecessary LLM latency.

**Implication:**
The `memoryInference` process is safe to run frequently (e.g., every 15 minutes in `akm-improve-quick`) without risk of infinite loops or redundant processing. The cache acts as a natural throttle for unchanged content.
