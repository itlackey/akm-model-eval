# Print MD Independent Rendering Pattern

This document describes the rendering mechanics of `document-renderer`, specifically how it processes multiple markdown files into a single output stream and the implications for plugin authors regarding state management and CSS scoping.

## Rendering Mechanism

`document-renderer` renders markdown files independently by iterating over a manifest of files. The core logic in `index.ts` concatenates rendered HTML:

```typescript
bodyContent += md.render(content) + chr10
```

While the `markdown-it` parser state (e.g., `chapterOpen`, `pageOpen` flags) resets for each file, the rendered HTML divs persist in the concatenated output string. This creates a specific risk: any layout marker scope that is not closed at the End Of File (EOF) of a source file becomes a silent ancestor div wrapping every subsequent file's content.

## Implications for Plugin Authors

Because of this concatenation behavior, three critical issues arise:

1.  **Wrapper Closure:** Any plugin that opens wrapper divs (e.g., for chapters or pages) MUST ensure they are closed at the EOF of the current file. Failure to do so leaks the scope into subsequent files.
2.  **CSS Scoping Leakage:** CSS rules scoped to classes like `.page.X` or `.chapter.X` can inadvertently match content from completely unrelated files if those wrappers leaked. This breaks the isolation expected between independent files.
3.  **Paged.js Inheritance:** Paged.js inherits this leaked nesting when it clones content into output pages, potentially causing layout errors or incorrect pagination boundaries.

## Best Practices

Always verify EOF cleanup in `markdown-it` plugins that emit wrapper tokens. Ensure that any open structural elements are explicitly closed before the file rendering completes to maintain isolation between independent markdown sources.
