In AKM v0.8+, the storage model is explicitly split across four directory families to separate concerns cleanly and prevent cross-contamination of state:

1. **Config** (`$CONFIG`/`AKM_CONFIG_DIR`, default `~/.config/akm`): Contains exactly one durable file, `config.json`. This is the single source of truth for runtime configuration (LLM profiles, sources, registries). Project-level `.akm/config.json` files are deprecated and no longer merged.

2. **Cache** (`$CACHE`/`AKM_CACHE_DIR`, default `~/.cache/akm`): Holds ephemeral artifacts including registry mirrors (git/npm clones), website mirrors, HF embedding models, the `registry-index` cache, config backups, semantic-status.json, ripgrep binaries, and task logs/history. These contents are safe to clear independently without affecting state or knowledge.

3. **Data** (`$DATA`/`AKM_DATA_DIR`, default `~/.local/share/akm`): Hosts SQLite databases (`state.db`, `index.db`) and the global lockfile (`akm.lock`). `state.db` stores events (append-only log) and a dormant proposals table. `index.db` holds embeddings, FTS indexes, graph data, and utility scores. This is the only location for non-regenerable state.

4. **Stash** (`$STASH`/`AKM_STASH_DIR`, default `$BUNDLE_ROOT`): The writable workspace for assets (lessons, wikis). It contains `.akm/config.json` (legacy), `.akm/proposals/` (filesystem-based queue), and asset files. The primary stash is git-initialized by `akm init`. Each source has its own metadata directory inside it.

This strict separation ensures that heavy read-only caches don't pollute the writable stash, and that global state (events/index) doesn't interfere with per-project knowledge bases.
