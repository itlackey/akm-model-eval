# Zero-Dependency Skill Architecture

This asset documents the architectural decision to build specific skills (`twitter`, `instagram`, `email-automation`) with **zero external dependencies**, relying exclusively on Node.js native modules.

## When to use
Use this reference when evaluating deployment constraints, security posture, or startup performance for new skills. If a skill requires an `npm install` step or relies on a framework-specific runtime (like Bun), consult the corresponding specific asset instead of this one.

## Implementation Details
All scripts in the following directories adhere to the zero-dependency constraint:
- `skills/social-media/twitter`
- `skills/social-media/instagram`
- `skills/email-automation`

### Native Modules Used
The implementation leverages only built-in Node.js capabilities:
- **`node:fs`**: Handles all file I/O operations.
- **`node:crypto`**: Manages OAuth signing (Twitter) and hashing algorithms.
- **Native `fetch`**: Performs HTTP requests without external agents like `axios` or `node-fetch`.

### Comparison with Dependent Skills
This approach contrasts with the `skills/social-media/bluesky` skill, which utilizes Bun and requires specific packages (`@atproto/api`, `@atproto/xrpc`). The zero-dependency skills are designed for environments where adding external layers is undesirable or impossible.

## Benefits
Adhering to this architecture provides:
- **Universal Deployability**: Scripts run in any environment (CI/CD pipelines, cron jobs, containers) without dependency resolution overhead.
- **Reduced Attack Surface**: Fewer packages mean fewer potential vulnerabilities and a smaller footprint for supply chain attacks.
- **Faster Startup Times**: Elimination of module loading and initialization delays associated with external libraries.
